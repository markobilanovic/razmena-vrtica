# Production Deployment Guide

This guide covers deploying Razmena Vrtica to production with a managed PostgreSQL database.

## Prerequisites

- Production server (VPS, cloud instance, or container platform)
- Domain name configured
- SSL certificate (Let's Encrypt recommended)
- Managed PostgreSQL database service

## Database Setup: Supabase (Recommended)

**Why Supabase for Razmena Vrtica:**
- **PostgreSQL-based**: Full compatibility with existing schema
- **EU hosting**: Available in Europe for GDPR compliance  
- **Developer-friendly**: Great dashboard, automatic backups
- **Built-in features**: Authentication, real-time, storage
- **Cost-effective**: Generous free tier, transparent pricing

### Quick Supabase Setup

1. **Create project** at [supabase.com](https://supabase.com)
2. **Choose EU region** (Europe Central for Serbia)
3. **Get connection string** from Settings > Database
4. **Follow detailed setup**: See `SUPABASE_SETUP_GUIDE.md`

### Alternative Options (if not using Supabase)

#### DigitalOcean Managed Database
```bash
doctl databases create razmena-vrtica-prod --engine postgres --version 16 --size db-s-1vcpu-1gb --region fra1
```

#### AWS RDS
```bash
aws rds create-db-instance --db-instance-identifier razmena-vrtica-prod --db-instance-class db.t3.micro --engine postgres
```

### Database Configuration

1. **Create production database:**
   ```sql
   CREATE DATABASE razmena_vrtica;
   ```

2. **Configure connection security:**
   - Enable SSL/TLS connections
   - Restrict access to application server IPs only
   - Use strong passwords (generated by service)

3. **Set up automated backups:**
   - Daily backups with 7-day retention minimum
   - Point-in-time recovery if available

## Environment Configuration

### 1. Create Production Environment File

Copy and configure the production environment:
```bash
cp backend/.env.production.example backend/.env.production
```

### 2. Update Production Variables

Edit `backend/.env.production`:

```env
# Production Environment Configuration
NODE_ENV=production

# Frontend URL (your actual domain)
FRONTEND_URL=https://razmena-vrtica.rs

# JWT Secret (generate a secure key)
JWT_SECRET=your-super-secure-jwt-secret-key-here

# Database (use your managed database credentials)
DB_HOST=your-production-db-host.com
DB_PORT=5432
DB_USERNAME=your-db-user
DB_PASSWORD=your-secure-db-password
DB_NAME=razmena_vrtica
DB_SSL=true

# Mailgun Configuration (production domain)
MAILGUN_API_KEY=your-production-mailgun-api-key
MAILGUN_DOMAIN=razmena-vrtica.rs
MAILGUN_FROM=Razmena Vrtica <noreply@razmena-vrtica.rs>
MAILGUN_EU=true

# Additional Production Settings
LOG_LEVEL=info
CORS_ORIGIN=https://razmena-vrtica.rs
```

### 3. Generate Secure JWT Secret

```bash
# Generate a secure JWT secret
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

## Deployment Steps

### 1. Prepare Application

```bash
# Install dependencies
npm install

# Build shared package
npm run build:shared

# Build backend
cd backend && npm run build

# Build frontend
cd ../frontend && npm run build
```

### 2. Database Migration

```bash
# Run migrations on production database
cd backend
NODE_ENV=production npm run typeorm migration:run
```

### 3. Seed Production Data

```bash
# Seed kindergartens (if needed)
NODE_ENV=production npm run seed:kindergartens
```

### 4. Deploy Application

#### Option A: Docker Deployment

Create `docker-compose.prod.yml`:
```yaml
version: '3.8'
services:
  backend:
    build: ./backend
    environment:
      - NODE_ENV=production
    env_file:
      - ./backend/.env.production
    ports:
      - "3000:3000"
    restart: unless-stopped

  frontend:
    build: ./frontend
    environment:
      - NODE_ENV=production
    ports:
      - "3001:3000"
    restart: unless-stopped
```

Deploy:
```bash
docker-compose -f docker-compose.prod.yml up -d
```

#### Option B: PM2 Deployment

```bash
# Install PM2 globally
npm install -g pm2

# Start backend
cd backend
pm2 start dist/main.js --name "razmena-backend"

# Start frontend
cd ../frontend
pm2 start npm --name "razmena-frontend" -- start

# Save PM2 configuration
pm2 save
pm2 startup
```

### 5. Configure Reverse Proxy (Nginx)

Create `/etc/nginx/sites-available/razmena-vrtica`:
```nginx
server {
    listen 80;
    server_name razmena-vrtica.rs www.razmena-vrtica.rs;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name razmena-vrtica.rs www.razmena-vrtica.rs;

    ssl_certificate /path/to/ssl/cert.pem;
    ssl_certificate_key /path/to/ssl/private.key;

    # Frontend
    location / {
        proxy_pass http://localhost:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # Backend API
    location /api {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

Enable the site:
```bash
sudo ln -s /etc/nginx/sites-available/razmena-vrtica /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

## Backup Strategy

### 1. Database Backups

Most managed services provide automated backups, but you can also set up additional backups:

```bash
# Create backup script
#!/bin/bash
BACKUP_DIR="/backups/razmena-vrtica"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/backup_$DATE.sql"

mkdir -p $BACKUP_DIR
pg_dump $DATABASE_URL > $BACKUP_FILE
gzip $BACKUP_FILE

# Keep only last 30 days
find $BACKUP_DIR -name "backup_*.sql.gz" -mtime +30 -delete
```

### 2. Application Backups

- Code is in Git repository
- Environment files should be backed up securely
- User-uploaded files (if any) should be backed up

## Troubleshooting

### Common Issues

1. **Database Connection Errors**
   - Check SSL configuration
   - Verify firewall rules
   - Confirm credentials

2. **Email Not Sending**
   - Verify Mailgun domain verification
   - Check API key permissions
   - Confirm DNS records

3. **Frontend/Backend Communication**
   - Check CORS configuration
   - Verify API endpoints
   - Check reverse proxy configuration

sudo tail -f /var/log/nginx/error.log

journalctl -u nginx -f
